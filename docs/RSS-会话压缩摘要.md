# RSSYXY 会话压缩摘要

> 用途：在 Claude Code、Codex 或其他 AI 中开启新会话时，优先读取本文件，以此代替加载体积过大的旧会话。
>
> 更新时间：2026-08-24（Asia/Tokyo）

## 一、项目目标

RSSYXY 是面向个人使用的中文消息聚合与阅读服务。核心目标：

- 首选中文阅读；必要信息可以保留英文或日文原文。
- 聚合科技、日本市场、大数据、云架构、股票与金融领域的信息。
- 在站内展开并阅读全文，尽量避免点击标题后跳转到外部网站。
- 对外文标题、摘要或正文提供中文翻译或中文 AI 摘要。
- 消息源可由用户自行增加、减少、启用和停用。
- 没有服务器，优先依靠 GitHub Pages、GitHub Actions 和本机免费运行。
- 电脑在线时使用本地 LiteLLM、9Router、OmniRoute 等 AI 网关增强内容；电脑离线时网站仍可展示最后一次生成的数据。

## 三、当前架构

### GitHub 端

- GitHub Pages 负责托管静态前端，不需要付费服务器。
- GitHub Actions 负责构建和发布站点。
- 仓库中的静态数据用于展示最近一次抓取、翻译和整理后的内容。
- GitHub Pages 不能直接访问用户电脑上的 `127.0.0.1`，因此不能在网页请求时即时调用本地 LiteLLM。

### 本机端

- 本机定时执行抓取任务。
- 获取 RSS/网页信息后，按配置调用本地统一 AI 网关。
- AI 负责中文翻译、摘要、分类、去重或重要度判断。
- 处理结果写回项目的数据文件。
- 随后提交并推送 GitHub，由 GitHub Pages 自动更新。

### AI 网关

- 稳定入口：`http://127.0.0.1:21381`
- 路由顺序：OmniRoute → 9Router → LiteLLM。
- Claude Code 对外使用模型别名 `claude-sonnet-4-6`。
- 抓取 RSS 本身通常不消耗 AI Token；只有翻译、摘要、分类、内容分析等 AI 步骤消耗模型额度。
- 应优先使用本地或免费路由，并在 AI 不可用时保留原文和普通摘要，不能让整个抓取任务失败。

## 五、产品与界面偏好

- 默认语言必须是中文。
- 首页不要堆满标题；应突出少量高价值内容。
- 推荐采用“今日重点 + 分类流 + 稍后阅读”的信息结构。
- 卡片至少展示：中文标题、来源、发布时间、中文摘要、分类和重要程度。
- 点击卡片后在当前站点打开侧边抽屉、弹层或文章详情页。
- 详情中先显示中文内容，可切换“原文 / 中文”。
- 外部原文链接保留为次要操作，不能作为主要阅读路径。
- 相同文章的原文和中文版本应归为同一条信息，避免重复占据列表。
- 支持按来源、领域、语言和时间筛选。
- 后台消息源管理至少支持新增、编辑、启用、停用、删除和测试抓取。

## 六、站内阅读全文的边界

- RSS 自带全文时，可以直接保存并在站内展示。
- RSS 只有摘要时，需要本机抓取原网页并提取正文。
- 某些网站有登录、反爬、JavaScript 渲染或版权限制，可能只能保存摘要和原文链接。
- 保存正文时要保留来源、作者、发布日期和原文链接。
- 不应绕过付费墙；遇到受限内容只展示合法获得的摘要。

## 七、消息源管理建议

- 以一个可版本管理的配置文件作为消息源真相来源。
- 每个消息源建议包含：`id`、名称、URL、语言、领域、地区、启用状态、抓取方式、全文能力、更新时间和备注。
- 网站后台编辑可以先写入浏览器本地配置并导出文件；若需要跨设备永久保存，则使用 GitHub API、GitHub Issue 工作流或免费的外部数据库。
- GitHub Pages 是静态网站，不能单独承担带登录的在线后台写入功能。

## 八、每日工作流

1. 每天 06:30 Windows 计划任务启动本机脚本。
2. 读取已启用的消息源。
3. 抓取 RSS 或文章页面。
4. 规范化、去重并提取正文。
5. 调用本地 AI 网关完成中文翻译、摘要、分类和重要度判断。
6. 生成前端所需的静态数据。
7. 本机校验构建结果。
8. 提交并推送到 GitHub。
9. GitHub Actions 发布 GitHub Pages。
10. 用户醒来后打开网站查看最新内容。

## 九、容错原则

- AI 网关不可用：仍完成抓取，保留原文，稍后补翻译。
- 单个消息源失败：记录错误并继续其他消息源。
- 正文提取失败：保留 RSS 摘要和原文链接。
- GitHub 推送失败：保留本地生成结果，下次重试。
- 翻译结果与原文必须通过稳定文章 ID 关联，不能生成两条重复卡片。
- API Key 和网关密钥只能放在本机环境变量或 GitHub Secrets，不能提交到仓库。
